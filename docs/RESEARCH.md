# raw CLI Agent 架构全景调研与设计蓝图 (Architecture Research & Blueprint)

> 本文档是 `raw` 项目（`bpfio/raw`）的权威架构调研与技术设计报告，记录了对 Pi Agent、zcode-app-cli、ZCode 官方开源仓库以及 DeepSeek Harness 架构的最佳实践调研，并确立了项目的核心设计原则、防幻觉机制与演进路线。
> 同步归档于 Logbook 知识中枢：`project: "raw"`, `research_id: 24`。

---

## 一、 调研背景与使命定位

在政策调研与数据分析场景中，传统的通用 Coding Agent 常常面临两难困境：
1. **安全性与黑盒困境**：许多轻量工具采用二进制混淆包或依赖多层复杂补丁，代码无法白盒审计，存在供应链投毒与未授权数据外泄（Telemetry）风险；
2. **幻觉率与执行力脱节**：同为先进模型，在不同脚手架（Harness）下表现天差地别——缺乏严格闭环约束的 Agent 常常产生严重幻觉（捏造数据、指标前后矛盾、虚构文件），而过度复杂的框架则陷入漫长的 IPC 延迟与上下文爆炸。

**`raw` 的使命**：
打造一个**100% 白盒开源、零数据外泄、极低幻觉、极高执行力**的现代化 Agent CLI。
- **双擎核心**：深度整合 **GLM**（敏捷信息流探针）与 **DeepSeek**（长链因果逻辑推演）；
- **主攻领域**：**政策深度调研**（条文比对、脉络追溯、博弈推演）与 **严密数据分析**（指标穿透、勾稽核验、产能良率事实审计）；
- **终端交互**：继承 `@earendil-works/pi-tui` 的无闪烁差分渲染与渐进折叠手感。

## 二、 标杆方案与开源架构深度剖析

### 1. Pi Agent 生态 (`@earendil-works/pi`)
* **架构精髓**：
  - 由 Mario Zechner 与 Armin Ronacher 创立的 Earendil Inc. 打造，主打极简主义（Minimalism）；
  - 核心模块清晰分层：`pi-ai`（统一模型抽象）、`pi-agent-core`（无 UI 状态机循环）、`pi-tui`（差分渲染终端界面）；
  - **极简 4 大原子工具**：仅提供 `read`、`write`、`edit`、`bash`，将系统提示词压制在 1000 Token 以内；
  - **错误作为一等公民**：工具执行报错必须抛出显式 `Error`，核心层自动将其捕获并包装为结构化 `isError: true` 结果，促使模型自愈。
* **对 raw 的借鉴**：
  - 汲取其分层思想与 4 大原子工具设计；
  - 采用其 `@earendil-works/pi-tui` 差分渲染库构建终端。

### 2. zcode-app-cli (`kingsword09/zcode-cli` / `bpfio/raw` 前身)
* **架构精髓**：
  - **同进程零拷贝直连（Zero IPC）**：通过 `runtime-tui-bridge.ts` 将 Agent 运行时与 TUI 放在同一个 Node.js 进程中直接进行函数与事件传递，杜绝了 Localhost HTTP/Socket 的开销；
  - **嵌入式并发治理**：在 `runtime-sqlite-recovery.ts` 中针对 SQLite `SQLITE_BUSY` 建立了自适应指数退避与事务重试；
  - **严格预算管理**：`bounded-tool-text.ts`（单工具输出硬卡 64KB 限制）、`file-diff-budget.ts`（Diff 严格限制在 2000 行以内）。
* **对 raw 的警示**：
  - 从 Desktop 安装包提取压缩混淆 `vendor/zcode.cjs` 的做法属于严重的技术负债，27 个 AST/字符串补丁极易在版本升级中发生锚点漂移；
  - `raw` 必须彻底告别黑盒混淆二进制，走 100% 白盒自研路线。

### 3. zai-org/ZCode 官方开源仓库 (Apache-2.0)
* **架构精髓**：
  - 完整的 TypeScript Monorepo，`apps/zcode-cli` 包含完整的 Agent 运行时与工具契约；
  - 经过数百万用户验证的 System Prompt、Tool Schema 和 Preflight 校验机制极其严密，是低幻觉的重要基石。
* **对 raw 的借鉴**：
  - 借鉴其成熟的提示词纪律与工具调用前置校验，但避免其庞大的 React+OpenTUI 依赖负担。

### 4. DeepSeek Harness 最佳实践与 Deep Code (`deepcode-cli`)
* **架构精髓**：
  - **思考流隔离铁律（CoT Stripping）**：DeepSeek-R1 的 `<think>` 或 `reasoning_content` 是中间推演过程，**严禁将其回喂至多轮对话历史中**。将旧思考流混入历史会导致模型陷入递归自我模仿循环，并极度浪费 Token；
  - **零样本（Zero-Shot）纯净纪律**：R1 依赖内生推理，复杂的 Few-shot 样例会诱发其刻板套用模板，清晰简洁的零样本约束效果最佳；
  - **规划-执行双模协作（Planner-Worker）**：R1 专精深度因果规划与证据一致性核验，快速模型（如 GLM-5.3 Flash / DeepSeek-V3）专精高频工具执行。

## 四、 核心设计原则 (Design Principles)

1. **状态所有权单一（Single State Owner）**：
   运行时（Runtime / Event Store）是唯一的单一事实源；TUI 界面坚决不维护独立状态副本，仅作为**纯投影（Projection）**被动响应事件。
2. **原子工具极简化（Minimalist Primitives）**：
   坚持 4 大通用原子工具（`read`, `write`, `edit`, `bash`）加上专为研判设计的轻量 `fetch`。工具契约越短越清晰，模型决策路径越短，幻觉率越低。
3. **同进程零拷贝直连（In-Process Direct Calls）**：
   Agent 内核与终端界面运行在同一个 Node/Bun 进程中，以内存事件与函数调用通信，消除任何 Localhost 跨进程网络开销。
4. **确定性验证闭环（Deterministic Closed-Loop）**：
   先读后写（Read-before-Write）、执行后检查真实状态码、编辑输出结构化 Diff。

## 五、 如何防止幻觉？（防幻觉工程体系）

针对数据分析与政策研判场景，构建五重防幻觉闭环机制：

1. **信息流完整性与有界截断（Bounded IO）**：
   - 工具输出超过 64KB 时，保留稳定的头部与滚动尾部，绝不断裂 JSON 语法闭合，防止模型因信息缺失而凭概率补全。
2. **真实退出码与错误反馈（Error as Feedback）**：
   - 执行出错必须返回真实 Stderr，转化为 `isError: true` 错误块，迫使模型感知失败并自我修正。
3. **DeepSeek 思考流生命周期隔离（CoT Stripping）**：
   - 剥离多轮对话历史中的上一轮 `reasoning_content`，保持多轮上下文纯净。
4. **拒绝 Few-Shot 模板过载（Zero-Shot 纯净纪律）**：
   - 保持提示词精炼、静态、高信噪比，消除自相矛盾的要求。
5. **证据一致性审查门（Evidence Consistency Gate）**：
   - **0/1 与 1-100 维度分离**：严格区分“有无”与“水平高低”（例如：引用良率数据即等于承认主体具备产线与产能，严禁用良率低推导无产能）；
   - **数据对账自检**：在分析多方宏观数据时，强制模型输出数据勾稽对照，发现矛盾必须显式汇报。

## 六、 如何提高执行效率与吞吐？（极速调优方案）

1. **KV Cache / Prompt Caching 前缀锁定**：
   - 将不变的 System Prompt 与 Tool Schemas 置于消息数组最前端，保持字节级静态；
   - 确保大模型服务端 **KV Cache 命中率维持在 80% 以上**，首字延迟（TTFT）压制在 300 毫秒以内。
2. **GLM + DeepSeek 快慢双擎流水线**：
   - **快通道（GLM-5.3 Flash / Plus）**：高速抓取长篇政策公报、清洗表格 CSV，吞吐量大、响应敏捷；
   - **慢通道（DeepSeek-R1 / V3）**：当且仅当需要深入推演因果逻辑、对账审计时触发，快慢解耦。
3. **终端差分双缓冲渲染**：
   - 仅对变动的终端字符矩阵输出 ANSI Escape 码，CPU 占用低于 1%，流式输出不闪烁。
