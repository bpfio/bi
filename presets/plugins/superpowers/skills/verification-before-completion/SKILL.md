# Verification Before Completion：完工自验铁律

唯一原则：**未验证即未完成（Unverified ≠ Done）**。
"完成"是一个可证据化状态，不是一个感觉。没有证据的"通过"等于"没通过"，
甚至是更坏的东西——它制造虚假进度。

## 1. 什么时候触发

- 准备说"做完了 / 提交了 / 修好了 / 可以交付了"（对用户、对协调者、对自己）
- 准备发出任务完成报告或状态翻转（running → review/closed）
- 准备删除或收尾工作现场（worktree、临时文件、调试代码）

以上任一时刻，必须先走完第 3 节清单。清单没走完，不许宣布完成。

## 2. 验证金字塔（由快到慢，逐层跑）

| 层 | 验证内容 | 典型命令 | 不通过怎么办 |
|----|---------|---------|-------------|
| L1 语法/编译 | 代码能编译、能解析 | `build` / `tsc` / `python -m py_compile` | 修复，禁止继续 |
| L2 静态检查 | lint / type check | `eslint` / `ruff` / `mypy` | 修复或显式记录豁免理由 |
| L3 单元测试 | 逻辑正确性 | 项目测试命令（全量，不是只跑新写的） | 修复；禁止只跑改动过的用例 |
| L4 端到端 | 真实场景走通 | 启动服务 + 实际调用 / 脚本冒烟 | 修复；L4 失败则任务未完成 |
| L5 回归 | 没改坏别的东西 | 全量测试套件 + 受影响路径抽查 | 定位影响面，修复或回滚 |

规则：

- 层与层不可跳。L4 存在时，L1-L3 通过不构成完成条件。
- "改动了 A 模块只测 A 模块"是错的——跑全量，回归损失总是超出直觉。
- 命令必须真实执行并捕获输出，禁止凭记忆断言"这个命令上次是通过的"。

## 3. 宣布完成前检查清单

### 3.1 验证执行

- [ ] L1-L5 中适用于本任务的每一层都真实跑过（适用性判定写进证据）
- [ ] 所有验证是在**最终代码状态**上跑的（改完最后一行后重跑，不是拿旧结果凑数）
- [ ] 测试不是恰好通过的侥幸：抽查至少 1 个边界/异常路径

### 3.2 证据留痕（无证据 = 没验证）

- [ ] 每个关键验证命令的**原始输出**已留存（终端记录 / 日志文件 / 报告引用）
- [ ] 证据包含：命令、时间、结果（通过数/失败数）、关键输出行
- [ ] 失败过的验证保留失败现场证据与修复后的对比（证明真的修过）
- [ ] 报告中的每个"通过"声明都能回指到一条具体证据

### 3.3 交付物完整性

- [ ] 交付物清单与任务 DoD 逐项对照，无遗漏项
- [ ] 调试残留已清理：print/console.log、注释掉的代码、临时硬编码、调试开关
- [ ] 新增依赖已写入清单文件（package.json / requirements.txt / go.mod 等）
- [ ] 文档与实际行为一致（改了行为就必须改文档）

### 3.4 诚实性自检

- [ ] 我有没有任何一项是"假设它会过"而没实际跑的？→ 有就去跑
- [ ] 我有没有把"写了"说成"完成了"？→ 写了只是开始
- [ ] 我有没有隐瞒已知的小问题？→ 如实列出，标注"已知遗留"

## 4. 证据留痕格式（最小模板）

```
[验证证据] <任务或变更标识>
- L1 编译:     <命令> → OK（0 error）
- L2 lint:     <命令> → 0 warning（<n> 项豁免，理由：<...>）
- L3 单测:     <命令> → <passed>/<total> passed, 0 failed
- L4 端到端:   <场景描述> → <观察到的实际结果>
- L5 回归:     <命令> → 全量通过 / 失败 <n> 项（处理：<...>）
- 已知遗留:    <如实列出，含影响面与后续计划>
```

## 5. 禁止行为（红线）

- **口头宣称通过**：说"测试都过了"但拿不出输出——等于撒谎
- **选择性跑测试**：只跑自己新写的用例，不跑存量
- **旧证据新声明**：改完代码拿改动前的测试结果交差
- **"应该没问题"**：这三个字出现的地方就是没验证的地方
- **把验证推给下游**："reviewer 会发现的"——发现之时你的工作已报废一轮

## 6. 与其他技能的衔接

- 宣布完成时若发现 Bug → 转入 systematic-debugging，不许边猜边改
- 交付前的双阶段审查（subagent-driven-development）会复核本清单——
  本技能是自证，SDD 是他证，两者都不可省
